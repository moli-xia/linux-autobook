面板版本 2.2 · 适用于 Ubuntu 22.04 / 24.04、Debian 12

这份文档假设你完全没有接触过本项目，从「机器刚装好系统」讲到「任务跑起来」。

## 三分钟快速上手

单机全功能部署（一台机器同时做网关和 Worker）：

```bash
curl -fsSL https://raw.githubusercontent.com/moli-xia/linux-autobook/main/install.sh -o install.sh && sudo bash install.sh
```

安装脚本会问三个问题，全部可以直接回车用默认值：

| 提问 | 直接回车的效果 | 什么时候需要自己填 |
| --- | --- | --- |
| 本机角色 | 网关 + Worker | 多机部署时按下面「常见部署方案」选 |
| 管理域名 | 使用自签名证书 | 有域名并已解析到本机，想要浏览器不报警告 |
| 管理面板端口 | 8766 | 8766 被占用，或想换个不显眼的端口 |

装完屏幕会打印面板地址，例如 `https://23.95.32.134:8766/`。
浏览器打开它 → 用 `admin` / `admin` 登录 → 左侧点「配置向导」→ 按步骤填完 →
点「连通性检测」→ 全绿之后点「启动 Worker」。完成。

> 自签名证书会让浏览器显示「不安全」警告。这是预期行为，点「高级 → 继续访问」即可。
> 数据仍然是加密传输的，只是证书没有第三方机构背书。

## 先理解两个角色

整个系统只有两种角色，看懂这张表就不会配错：

| 角色 | 干什么 | 需要什么 | 能装几台 |
| --- | --- | --- | --- |
| **百度下载网关** | 持有百度账号，把群文件转存到自己网盘并高速下载，再通过 HTTPS 交给 Worker | 一个已加入目标群的百度账号（推荐 SVIP） | 通常 **1 台** |
| **任务 Worker** | 从任务网站领任务，向网关要文件，解压 → 转 PDF → 上传结果网盘 → 回填链接 | 任务网站令牌、结果网盘账号、网关地址与令牌 | **任意多台**，加机器就是加产能 |

关键点：**Worker 上永远不需要百度账号**。百度登录态只存在于网关那一台机器上，
这样加机器不用反复扫码，账号风险也集中在一处。

安装时选「网关 + Worker」表示这台机器两个角色都装，Worker 通过
`https://127.0.0.1:8765` 连接本机网关——这是单机用户的推荐选择。

## 安装

> 想用 Docker 部署？见 **[Docker 部署说明](Docker部署说明.md)**，
> 镜像同时支持 amd64 与 arm64，一条 `docker compose up -d` 就能起来，
> 面板功能与下面的 systemd 部署完全一致。

### 在线安装（推荐）

```bash
curl -fsSL https://raw.githubusercontent.com/moli-xia/linux-autobook/main/install.sh -o install.sh && sudo bash install.sh
```

### 从源码安装

```bash
git clone https://github.com/moli-xia/linux-autobook.git
cd linux-autobook
sudo bash install.sh
```

### 非交互安装（写脚本时用）

```bash
# 单机全功能
sudo bash install.sh --action install --role all --non-interactive

# 中心网关，带域名和免费证书
sudo bash install.sh --action install --role gateway --domain gw.example.com --acme-email me@example.com --non-interactive

# 计算节点
sudo bash install.sh --action install --role worker \
  --gateway-url https://gw.example.com:8765 \
  --gateway-token 与网关一致的令牌 --non-interactive
```

### 安装后的常用命令

安装脚本会注册一个 `autobook` 命令，以后不用再找脚本在哪：

```bash
sudo autobook              # 打开菜单：安装 / 更新 / 状态 / 卸载
sudo autobook --action status
sudo autobook --action update
sudo autobook --action uninstall
```

卸载默认会先把配置和 runtime 数据备份到 `/var/backups/linux-autobook/`；
加 `--purge` 则不备份、彻底清除。

### 装到哪里了

| 路径 | 内容 |
| --- | --- |
| `/opt/autobook-linux/` | 程序代码、Python 虚拟环境、runtime 工作目录 |
| `/etc/linux-autobook/` | 配置文件（0600 权限，仅 root 可读） |
| `/etc/systemd/system/autobook-*.service` | 三个 systemd 服务 |
| `/var/backups/linux-autobook/` | 卸载或手工备份产生的归档 |

## 第一次登录

1. 打开安装脚本输出的地址，例如 `https://你的IP:8766/`
2. 用户名 `admin`，密码 `admin`
3. 登录后页面顶部会有一条黄色提醒：**当前仍在使用默认密码**

面板会强制把你带到「管理账号」页。请立即修改：

- 用户名可以改成不容易猜的名字（3–40 位字母数字）
- 新密码至少 8 位，**强烈建议 16 位以上随机串**
- 保存后所有登录会话都会失效，需要用新密码重新登录

> 面板监听在公网端口上，root 权限运行。默认密码不改等于把服务器交出去。
> 更稳妥的做法是用防火墙把 8766 端口限制到你自己的 IP：
> `sudo ufw allow from 你的IP to any port 8766 proto tcp`

## 面板每一页都做什么

### 概览

一屏看清整台机器的状态：

- **顶部四块**：主机名、CPU 负载、内存、磁盘。磁盘低于 10 GB 会变黄，低于 3 GB 变红——
  转换大部头书籍时临时文件很占空间，这里要留意。
- **服务卡片**：每个服务显示运行状态、开机自启、已运行时长、内存占用和重启次数。
  按钮直接启动 / 停止 / 重启，旁边一键跳转日志。
- **待办事项**：所有阻止服务启动的配置问题，一条一条列出来，每条右边有「去填写」按钮，
  点了直接跳到配置页对应的输入框并自动聚焦。**这一栏空了就说明可以启动服务了。**
- **系统信息**：角色、版本、外部命令（7z / aria2c）是否安装、工作目录占用多少空间。

### 配置向导

第一次部署走这里。它把配置拆成带编号的步骤，每步只显示该步真正必需的字段，
填完点「保存」，完成的步骤序号会变成 ✓。走到最后一步就是「检测并启动」。

向导里不会出现任何高级参数——那些都有合理默认值，需要时再去「配置」页调整。

### 配置

全部参数都在这里，按角色和用途分组：

- 右上角「常用 / 全部参数」切换：常用视图只显示日常会改的项，避免被几十个参数淹没。
- 每个字段下面都有一句人话说明和示例值，不用去翻文档。
- 必填项没填会显示红色「必填」标记，填好后变成绿色「已填写」。
- 密码类字段保存后不再回显，**留空提交表示保持原值不变**，不会被清空。
- 数字字段有上下限校验，填 99 个并发这种明显错误会被直接拒绝并说明原因。
- 底部有常驻的保存条，改完点「保存配置」；如果改动影响到正在运行的服务，
  面板会提示需要重启哪个服务才能生效。

### 连通性检测

这是排错最快的入口。点一次按钮，逐项实测并给出结论：

**Worker 节点检测**

| 检测项 | 说明 |
| --- | --- |
| 配置完整性 | 必填项是否齐全 |
| 磁盘空间 | 剩余空间是否够转换用 |
| 7-Zip / aria2c | 外部命令是否安装 |
| 任务网站可达性 | 能否访问网站 |
| **Worker 令牌** | 用一次不会产生任何副作用的心跳请求验证令牌是否被网站接受 |
| 下载网关连接 | TLS 是否可信、令牌是否正确、网关当前有多少任务 |
| 结果网盘登录 | 用真实账号密码登录 Cloudreve，直接验证账号密码对不对 |
| 工作目录权限 | 服务账号能否写入工作目录 |

**网关节点检测**

| 检测项 | 说明 |
| --- | --- |
| 网关证书 | 证书和私钥是否匹配、有效期、SAN |
| 百度登录态 | Cookie 是否还有效 |
| 目标群文件库 | 该账号能不能看到目标群、群里有多少文件 |
| 网关本机自检 | 本机端口上的网关服务是否正常响应 |

每一项失败都会附带「建议」，直接告诉你去改哪个配置或点哪个按钮。
检测全程只读，不会领取任务、不会修改任何数据。

### 百度登录（仅网关节点显示）

三步图示 + 二维码：点「生成二维码」→ 手机百度网盘 App 扫一扫 → 手机上确认。
页面每 5 秒自动刷新状态，会依次显示「等待扫码 → 等待手机确认 → 登录成功」。
登录成功后面板自动重启网关服务，无需手工操作。

登录态以 0600 权限保存在 `/opt/autobook-linux/runtime/baidu_credentials.json`，
页面上不会显示任何 Cookie 内容。登录态过期时重新扫一次即可。

### 运行日志

选服务、选行数、关键字过滤、自动刷新开关。日志里的百度下载直链、令牌、密码
会被自动替换成 `[已隐藏]`，可以放心截图求助。

### 任务记录（仅 Worker 节点显示）

从 Worker 日志还原出的任务表格：任务号、书名、状态（处理中 / 已完成 / 失败）、
最新进度或失败原因、时间。已完成的任务可以直接点开交付链接。

### 任务管理

「任务记录」看的是本机日志，这一页看的是**整个站点**：每个任务由哪台服务器执行、跑了多久、
最新进度是什么，都在一张表里。上方四个数字分别是执行中、排队中、已完成、失败。

一台 Worker 领了任务却停止上报心跳超过 5 分钟，该行会标上「失联」——这通常就是你要找的那一条。

**删除功能只在网关主服务器上出现**，纯 Worker 节点只能查看。可以勾选若干条后「删除选中」，
也可以按状态批量清空（失败 / 已完成 / 排队 / 全部）。删除是直接把任务从网站移除，**不可恢复**；
清空「全部」会连正在执行的任务一起删掉，正在处理它们的 Worker 会在下次上报时失败。

### 解压密码字典（仅 Worker 节点显示）

加密压缩包会按字典顺序逐个尝试密码（程序总是先试空密码）。
程序**内置了 307 条常见密码**，新装的节点开箱即用，不需要自己准备字典。

页面上可以：

- **添加**：顶部输入框敲入密码，回车或点「添加」；重复的会被拒绝并提示；
- **修改**：每行右侧「修改」→ 就地编辑 → 回车或点「保存」；
- **删除**：每行右侧「删除」，会先确认；
- **搜索**：字典大了以后用搜索框快速定位；
- **补充内置字典**：只把你缺少的内置密码补进来，**保留**你自己加的；
- **恢复为内置字典**：用内置列表**覆盖**当前字典，自己加的会丢失（会先确认）；
- **批量文本编辑**：一次粘贴/整理几百条，保存时自动去重。

修改立即生效，不需要重启 Worker——下一个任务就会用新字典。
文件权限 0600，页面顶部会显示它的实际路径。

### 节点管理（主服务器上显示）

装了网关角色的机器会多出这一页，用来统一管理所有 Worker 服务器，不用再逐台登录面板。

**把一台 Worker 接进来（两步）**

1. 在 **Worker 的面板** 打开「维护 → 接入主服务器」，点「复制」拿到一串 `AUTOBOOK1:…` 开头的接入码；
2. 在 **主服务器的面板** 打开「节点管理」，粘贴进去，点「添加节点」。

接入码里已经包含对方的地址、证书指纹和一个专用令牌，不需要再手工配置地址或拷贝证书。
它**不包含管理员密码**——主服务器只能查看状态和操作服务，无法改对方的管理账号。

**这一页能做什么**

- 顶部四个数字：节点总数 / 离线数 / 运行中的 Worker / 待处理问题总数；
- 每个节点一张卡片：在线状态、CPU 负载、内存、磁盘、面板版本、是否 Docker 部署；
- 卡片里直接**启动 / 停止 / 重启**对方的网关和 Worker；
- **任务记录**：把对方最近处理的书目拉过来看；
- **日志**：读对方的服务日志（同样自动打码）；
- **连通性检测**：在对方机器上跑完整的九项检测，结果显示在主服务器这边；
- 重命名、移除、直接打开对方面板。

节点状态每 30 秒自动刷新一次，页面每 5 秒读一次缓存，所以打开就有数据。
某个节点连不上不会影响整页，只会把那张卡片标成离线并显示原因。

**配置下发（新增 Worker 最省事的方式）**

勾选节点 + 勾选要下发的内容，点「开始下发」：

| 内容 | 下发什么 |
| --- | --- |
| 任务网站 | 网站地址、Worker 令牌 |
| 结果网盘 | Cloudreve 地址、账号、密码、上传目录、有效期 |
| 下载网关 | 共享令牌、**本机的网关地址**、以及**网关证书**（自动装好并填进对方配置） |
| 解压密码字典 | 把本机字典完整同步过去 |

其中「下载网关」这项省掉的正是以前最麻烦的一步：不用再 scp 证书、不用手填路径。
下发会覆盖对方对应的配置项，完成后目标节点需要重启 Worker 才生效。

**安全说明**

- 节点之间用专用令牌认证，不共享管理员密码；
- 每次连接都校验对方证书的 SHA-256 指纹，自签名证书也不怕中间人；
- 对方重新生成证书或点了「重新生成」接入码后，主服务器会立刻报「指纹不一致」或
  「令牌被拒绝」，重新复制接入码即可；
- 主服务器能访问的接口是固定白名单：状态、日志、任务、配置、密码字典、服务启停。
  管理账号、会话、接入码和节点管理本身都不在其中。

### 维护

一键处理常见问题，执行过程实时显示在下方控制台：

| 按钮 | 什么时候点 |
| --- | --- |
| 修复系统依赖 | 检测提示 7z 或 aria2c 缺失 |
| 修复目录权限 | 日志出现 Permission denied |
| 重新生成网关证书 | 换了 IP/域名，或证书损坏。生成后必须把新的 `gateway.crt` 发给所有 Worker |
| 备份配置 | 升级前、改大动作前 |
| 预览可清理的文件 | 想知道网盘里有多少空间可以释放。只统计，不删除 |
| 立即清理网盘 | 需要马上腾出空间。会**永久删除**过期文件 |
| 更新程序 | 拉取 GitHub 最新代码并重装，配置和数据保留 |
| 重启管理面板 | 面板本身异常 |

#### 存储清理是怎么工作的

每个任务都会把成品 PDF 传到结果网盘并生成一个 N 天后失效的分享链接。**链接失效不等于文件被删除**，
所以不清理的话网盘会一直涨。下载环节也一样：群文件要先转存到自己的百度网盘再下载，正常情况下下载完
立刻删除，但任务超时、进程被杀、转存重试产生 `书名(1).epub` 这类副本时，都会留下残留。

现在两处都会自动清理，**服务启动 2 分钟后跑第一次，之后每隔「清理间隔」再跑一次**：

| 清理对象 | 由谁执行 | 删除条件 |
| --- | --- | --- |
| 结果网盘的成品文件 | Worker | 上传时间早于「分享有效期 + 过期宽限期」 |
| 百度网盘中转目录 | 网关 | 停留时间超过「残留文件清理时限」 |

判断用的是**文件上传到网盘的时间**，不是文件本身的修改时间——后者可能是几年前的原始文件日期，
拿它当依据会把刚交付的书删掉。取不到时间的条目一律跳过，目录永远不删。

> **百度侧可能删不掉：errno=132**
> 如果日志里出现「删除网盘临时文件被拒绝 errno=132」，说明百度要求该账号先完成一次**安全验证**
> 才允许任何文件管理操作。这是百度的账号安全策略，换请求写法绕不过去，只能：
> 用百度网盘 App 登录同一账号完成一次安全验证，然后回面板重新扫码登录；在此之前中转目录
> 只能在百度网盘里手动清理。
>
> 影响有限：群文件短期直链是主路径，只有直链失效才会走转存，累积速度很慢。
> 结果网盘的清理不受影响。

不想自动清理就把「存储清理 → 自动清理」关掉，改用上面的两个按钮手动处理。命令行等价物：

```bash
python3 tools/storage_sweep.py            # 预览
python3 tools/storage_sweep.py --execute  # 真删
```

还有一块 **本机角色**：直接在面板里把机器切换成「仅网关 / 仅 Worker / 网关 + Worker」。
systemd 部署会重跑安装脚本装好对应服务，容器部署直接切换托管进程，现有配置都会保留。

> 「更新程序」和「切换角色」会重启面板自身。systemd 部署下这两项交给独立的 systemd
> 单元执行，面板重启不会中断它们，刷新页面后仍能看到结果。
> 容器部署请改用 `docker compose pull && docker compose up -d` 升级。

## 配置项逐条说明

面板里每个字段下方都有说明，这里补充一些容易踩坑的点。

### 任务网站（Worker）

| 字段 | 说明 |
| --- | --- |
| 任务网站地址 | 必须 `https://` 开头，**结尾不要带斜杠或路径**，例如 `https://544544.xyz` |
| Worker 令牌 | 网站后台「文献传递 → Worker 管理」生成。复制时注意别带上首尾空格 |
| Worker 名称 | 多台机器**不能重复**，重复会导致网站上分不清是哪台机器 |
| 领取的任务队列 | 只有一台机器时选 `all`；多台分工时按类型拆 |

### 下载网关连接（Worker）

| 字段 | 说明 |
| --- | --- |
| 网关地址 | `https://主机:端口`。本机同时是网关就填 `https://127.0.0.1:8765` |
| 网关共享令牌 | 网关和所有 Worker **必须完全一致**。在网关机器的配置页复制 |
| 网关证书文件 | 网关用自签名证书 → 把网关的 `gateway.crt` 复制到本机并填路径；<br>网关用域名 + Let's Encrypt → **留空** |

复制自签名证书到 Worker 的命令：

```bash
# 在 Worker 上执行，把网关机器的证书拉过来
scp root@网关IP:/opt/autobook-linux/runtime/gateway.crt /opt/autobook-linux/runtime/gateway.crt
chown autobook:autobook /opt/autobook-linux/runtime/gateway.crt
```

然后在面板「网关证书文件」里填 `/opt/autobook-linux/runtime/gateway.crt`。

### 结果网盘（Worker）

Cloudreve 账号密码，成品 PDF 上传到这里并生成分享链接。
「连通性检测」会用真实账号登录一次，账号密码错了当场就能看出来。

### 存储清理（Worker）

| 字段 | 说明 |
| --- | --- |
| 自动清理 | 关掉之后网盘只增不减，需要自己定期手动清 |
| 清理间隔 | 默认 6 小时。文件量不大时调大到 24 小时也够用 |
| 过期宽限期 | 分享失效后再多留几天。默认 1 天，用来兜住时钟误差 |

配套的**残留文件清理时限**在「百度账号」一组里，属于网关。它的下限是单个任务可能的最长下载时间：
设得比这个短，正在下载的大文件会被当成残留删掉，任务随即失败。默认 6 小时留了很大余量。

### 处理参数（Worker）

**并发任务数**是最需要按机器配置调的参数：每个并发任务大约吃 1 个 CPU 核心和 1 GB 内存。

| 机器配置 | 建议并发 |
| --- | --- |
| 1 核 2 GB | 1 |
| 2 核 4 GB | 2 |
| 4 核 8 GB | 3 |
| 8 核 16 GB | 5–6 |

填太高的直接后果是内存耗尽，任务大批失败。

### 百度账号（网关）

| 字段 | 说明 |
| --- | --- |
| 目标群名称 / 群 GID | 填其一即可，**推荐填 GID**，比按名称查找稳定 |
| 百度代理 | 服务器能直连百度就留空。需要时填 `socks5h://127.0.0.1:10808` |
| BDUSS / STOKEN | 通常不用填，扫码登录更省事。两者必须同时填或同时留空 |

### 网关服务（网关）

监听端口默认 8765，**需要在防火墙或云厂商安全组放行 TCP 8765**，
否则其它机器上的 Worker 连不上。安装脚本会自动处理 UFW，云厂商的安全组要自己开。

## 常见部署方案

### 方案 A：一台机器全干（最简单）

安装时选「网关 + Worker」。Worker 走 `https://127.0.0.1:8765` 连本机网关，
证书路径已自动配好，什么都不用改。适合刚开始用、或者量不大的场景。

### 方案 B：一台网关 + 多台 Worker（推荐扩容方式）

**第一步，网关机器：**

```bash
sudo bash install.sh --action install --role gateway
```

装完在面板里：扫码登录百度 → 填群 GID → 复制「网关共享令牌」备用 → 启动网关。
再放行端口：`sudo ufw allow 8765/tcp`（云服务器还要在控制台安全组放行）。

**第二步，每台 Worker：**

```bash
sudo bash install.sh --action install --role worker
```

装完打开这台 Worker 的面板 →「维护 → 接入主服务器」→ 复制接入码 →
到主服务器面板「节点管理」粘贴添加。

然后在主服务器的「配置下发」里勾上这台节点、勾选「任务网站 + 结果网盘 + 下载网关」，
点下发——地址、令牌、网盘账号和网关证书会一次性装好，只剩 Worker 名称需要单独改
（每台不能重复）。最后在节点卡片上点「启动」。

加机器时重复第二步即可，网关不用动。

### 方案 C：给面板配域名和正式证书

DNS 把域名 A 记录解析到服务器，确保 80 端口没被占用，然后：

```bash
sudo bash install.sh --action install --role all --domain panel.example.com --acme-email me@example.com
```

脚本会申请 Let's Encrypt 证书并配置自动续期，之后浏览器不再报警告，
Worker 侧的「网关证书文件」也可以留空。

## 故障排查对照表

| 现象 | 原因与处理 |
| --- | --- |
| 浏览器提示「不安全」 | 自签名证书的正常表现，点「高级 → 继续访问」。介意就按方案 C 配域名证书 |
| 打不开面板 | `sudo systemctl status autobook-admin` 看状态；确认云厂商安全组放行了 8766 |
| 忘记面板密码 | `sudo rm /etc/linux-autobook/admin-state.json && sudo systemctl restart autobook-admin`，恢复成 admin/admin |
| 启动按钮点不动 | 概览页「待办事项」里还有未完成配置，逐条处理完按钮自动解锁 |
| 检测提示「网站拒绝了这个令牌」 | Worker 令牌错了，去网站后台重新复制，注意首尾空格 |
| 检测提示「TLS 校验失败」 | 网关用自签名证书但本机没配证书文件，按上文把 `gateway.crt` 复制过来 |
| 检测提示「网关拒绝了共享令牌」 | 两边令牌不一致，去网关机器复制正确的令牌 |
| 检测提示「结果网盘登录失败」 | Cloudreve 账号或密码错误，重新填一次密码 |
| 检测提示「尚未完成百度扫码登录」 | 去「百度登录」页扫码 |
| 检测提示「目标群文件库」失败 | 扫码用的百度账号没加入目标群，换账号重新扫码，或直接填正确的群 GID |
| 日志里 Permission denied | 维护页点「修复目录权限」 |
| 日志里 7z / aria2c not found | 维护页点「修复系统依赖」 |
| 任务大批失败、内存爆掉 | 并发任务数调低，参考上文机器配置对照表 |
| 百度下载 403 | 登录态过期，重新扫码；或该账号被限速，换 SVIP 账号 |
| 磁盘满了 | 概览页看工作目录占用；服务停掉后可清空 `runtime/work` 和 `runtime/downloads` |

## 安全须知

面板的防护措施：

- 全程 HTTPS，最低 TLS 1.2
- 管理密码用 PBKDF2-SHA256（600,000 轮）加随机盐存储，不保存明文
- 会话 Cookie 带 `Secure` + `HttpOnly` + `SameSite=Strict`
- 所有写操作校验 CSRF 令牌，登录失败按来源 IP 限速（10 分钟内 8 次锁定）
- 敏感字段永不回显给浏览器，日志中的令牌和下载直链自动打码
- 配置文件 0600 权限原子写入，只有 root 能读

需要你自己做的：

1. **立刻改掉默认密码**，用长随机密码
2. **用防火墙限制面板端口**，只允许自己的 IP 访问：
   ```bash
   sudo ufw allow from 你的IP to any port 8766 proto tcp
   sudo ufw deny 8766/tcp
   ```
3. 网关端口 8765 只需要对 Worker 机器开放，不要对全网开放
4. 定期在维护页点一次「备份配置」

面板以 root 运行是必需的：它要写 root-only 的配置、控制 systemd、安装系统依赖。
因此**面板端口的访问控制就是整台机器的访问控制**，请认真对待。
